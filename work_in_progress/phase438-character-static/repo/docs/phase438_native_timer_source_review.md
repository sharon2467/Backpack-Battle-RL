# Phase438 native Timer conditional invariant review

Independent static review, 2026-10-28. Scope and execution gate: `phase438_shared_combat_initial_rules_spec.md`. Read repository AGENTS and knowledge base. Only already-saved Godot3.6.2 source and the original baseline project were inspected. No Godot, collection, simulator, Python controls, old tests, or production changes were executed. This report does not promote any of the 64 Timer rows.

## Decision

**Conditional kernel rule proved; actual-project history premise not yet certified.** At completed, serialized native-operation boundaries, with valid Timer mode history (0/1), no external writes to the inherited internal-processing flags, and no reentrant native change-receptor callbacks during those flag setters:

`paused == false && idle_internal == false && physics_internal == false => processing == false => private_time_left == -1`.

The rule is about private C++ fields and the two actual Node bools. It does not infer the private value from public time_left zero or is_stopped. Current mode 0 and inside_tree true do not independently establish the history premise. Source identity and actual receiver/cut identity remain prerequisites, not default booleans.

## Source proof

Pinned source root: `data/phase251-logic-reset-timer-source-plan/Godot3.6.2/scene/main/`.

Use P=Timer.processing, A=Timer.paused, L=private time_left, M=process mode, I=idle internal bool, F=physics internal bool. timer.h:39-45 makes P and L private; 52-55 defines physics=0 and idle=1; 82-84 keeps _set_process private. timer.cpp:195-225 binds public methods and read-only public time_left, not P/L setters.

1. `!P => L == -1`: ctor writes L=-1/P=false (231-239). Only stop supplies false to _set_process, first writing L=-1 (117-120); set_paused reuses existing P (123-129). start writes L=wait_time then P=true (107-115). Internal notifications mutate L only after requiring P=true (48-79), and one-shot expiration calls stop. Consequently this implication holds after completed operations even without valid mode history, assuming no mid-setter reentrant mutation. External Node flag writes alone cannot mutate P/L, but invalidate the separate flag equivalence.
2. Stronger domain invariant: for M=0, F=P&&!A and I=false; for M=1, I=P&&!A and F=false. Node ctor initializes both flags false (node.cpp:3309-3310). Timer ctor initializes P/A false and M=1. _set_process updates the selected flag then P (170-180). start/stop and set_paused preserve the relation after return. Legal mode change either returns unchanged or transfers the one true selected flag to the other (144-164). When paused/stopped neither selected flag is true, so switching mode keeps both false. The inactive flag remains false throughout the completed transitions.
3. At A=false, both flags false forces P=false by (2), then L=-1 by (1). Public getters (136-142) are unnecessary to this proof.

`start` outside tree fails before mutation (108). Entry/exit do not reset P/L or internal bools: node.cpp:249-270 restores tree group registrations; 344-408 removes registrations and clears tree identity, not the flag bools. Native Timer has no exit-tree stop branch. Reentry is therefore not a fresh-timer proof but preserves the conditional invariant. Node ordinary set_process/set_physics_process (936-954,486-504) affect distinct fields. pause_mode/can_process (526-552,848-874) gate dispatch, not these bools. Thus tree pause or ordinary processing disabled does not imply Timer stopped.

Manual native internal notification still checks P, selected mode and selected internal bool before mutation (timer.cpp:49,66); manual READY uses ordinary start if autostart. Native timeout emits only after repeat addition or completed stop, so callbacks which perform valid-domain operations preserve the invariant even when nested. Script overrides can skip or wrap native calls but cannot directly address private C++ fields; they remain subject to the external Node API / mode / observer-identity premises. A script can shadow a public method, so returned snapshot values must be known native getters or a verified transparent script, not merely matching method names.

The invariant is **not an arbitrary instruction-boundary invariant**. start assigns L before P; stop assigns L before the selected flag/P transition; mode migration momentarily clears both flags. Node flag setters call _change_notify (519,969). The initial phase251 bundle lacks Object, but the parent identified the already-saved phase184 Object.cpp/h leaves; the bounded follow-up below resolves their dispatch semantics. No claim is made about arbitrary native plugins, data races, editor change receptors or observations/reentry inside those setters. Exclude those hooks or prove them separately; ordinary timeout callback reentry is already covered above.

Therefore ordinary GDScript cannot install a receptor through those names or override the native callback by declaring a same-named script method. A custom native registrar remains a distinct possibility outside the bounded plain-native domain.
* No add_change_receptor or _changed_callback registration/override occurs in the inspected Timer or Node sources. For a plain Timer with no external native registrar, this setter reentry edge is therefore closed. Non-TOOLS build identity closes it without the empty-set premise. **No --editor in a launch command does not prove !TOOLS_ENABLED.** A TOOLS build requires the bounded claim that no editor/native registrar attached a receptor to the target Timer; these two leaves alone do not certify all engine/module registrars absent.
* Object::notification (929-934) calls the complete native _notificationv before script_instance->notification. This confirms that normal script `_notification` delivery does not interrupt the middle of the Timer native method. Node's script _ready callback occurs before Timer's native READY branch in normal base-first dispatch, likewise at a completed operation boundary.
* A real hypothetical native-receptor counterexample illustrates why the premise matters: from running idle Timer, stop writes L=-1 then clears I; a one-shot guarded native receptor calls start(1) inside the flag-change callback, setting L=1/I=true/P=true; outer stop resumes and sets P=false. Subsequent set_paused(true), set_paused(false) clears I using false P but does not change L. Final paused=false/bothflags=false/P=false/L=1. This is outside ordinary script API closure, not a claimed observed project path.

Shortest remaining check if needed: reuse the already frozen startup/build identity and native-domain G02 premise to establish !TOOLS_ENABLED, or establish the ordinary non-editor plain-Timer/no-native-receptor-registration domain. ## Counterexamples and edge cases (static traces, not executed)

* Public zero alone: start with wait=1; a valid tick delta=1 leaves L=0, P=true and selected flag=true. Timeout condition is strictly L<0. Public getter returns 0 and is_stopped true.
* Repeat overshoot: wait=1, start, delta=3 yields L=1-3+1=-1 but P=true. Delta=4 yields L=-2/P=true. Only one wait_time is added per notification. Even private L=-1 does not imply !P.
* Paused: start(1), set_paused(true) gives L=1/P=true/both flags false. Thus A=false is indispensable.
* Inherited Node bypass, including exact saved public-zero shape: start idle wait=1; delta=1 gives L=0; call inherited set_process_internal(false); set_timer_process_mode(0). Final A=false/M=0/I=F=false/public0/is_stopped=true, but L=0/P=true. Node's public bindings (3120,3123) make this a real API escape outside the restricted domain.
* Invalid history despite valid current mode: start idle wait=1; delta=1; set_paused(true); set_timer_process_mode(2); set_paused(false); set_timer_process_mode(0). Final A=false/M=0/I=F=false/public0/is_stopped=true, but L=0/P=true. set_timer_process_mode contains no range rejection; on old mode 2 its switch has no branch. Therefore only checking current M in {0,1} is unsound. The same trace may retain another L, including negative repeat overshoot.
* Valid idle/physics migration, pause/change-mode/unpause, stop while paused and later unpause, tree removal/readdition, timeout restart, and manual notification are covered by the induction; none is independently a counterexample within the stated domain.
