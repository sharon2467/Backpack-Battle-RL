## 1. Requirements

从349/ffde十五源另建 `data/phase355-king-finite-source/staged`，为未来单P King固定A增加精确有限genuine准入和11输入SOURCE接口。正式75、349/350/351全部冻结保持；351实际独立FINAL由root接受，但不因此允许新运行。本轮只有文本/AST/compile，不import候选、不构造RNG/Engine、不initialize/step/run/build输入，不Godot/native/capture/expected/host/pool。

新profile `observer7-355-native-single-king-A/1`；SOURCE协议case `KING-K1-A-353`、observer版本 `7-king-single-A-355`，不是已创建的run。A精确引用351的5561B/b62bb554布局，合法fixture仅将HP/stamina转原input adapter的float表示并增加v8固定schema；无其他几何、slot、顺序或初态变化。仅双方class0、六ID{1,4,11,19,22,262}、全局单P:12 King、空gems/无私有注入。future native seeds global35301/util35302，生产32103及SHA双流政策不变。

不放宽旧KING_GENUINE_PROFILE fixture/runtime hash、旧UI/64role合同或其它profile；不实现collector/host/patch。没有新观察时绝不造nativeID/path/delta/时钟长度/initial资源。实现能够验证未来合法runtime的SOURCE接口，不冒充已实际提取、原版验收或生产76准入。

## 2. Design

预计只改genuine.py、engine.py；余13源（含state/headless/randomness/observed/Timer/FrameDriver）原字节。state现有King三字段/invu origin+bubble无profile gate，直接可复用；五旧private和68/75字段只在其对应物品出现时导出，K1无此类物品，因此不扩无关allowlist。

新genuine分支用静态A canonical fixture SHA准入，不钉尚不存在的runtime SHA；动态真实clock/topology用独立严格验证。旧函数只添加新profile分派，旧函数体以逆向删除新分派/字面量证明AST守恒。UI/RNG/fresh helper以旧SOURCE纯validator窄派生新名字/协议case/schema及A的39 guards，不临时覆写旧模块全局，不执行eval或导入旧tests作为运行依赖。

新finite engine复用真实FrameDriver/EngineFrameDriver及原integration ordinary/FX接线。processing-role集合按固定A和现_required_roles推导；不借旧64常数或旧八ID。实际node/nativeID/path/positions/priority来自合法input；约束两侧tick3/invu5、King Buff7/activation8/drag Icon1-child2及ready Timer0相对拓扑，fresh Timer mode/oneShot/wait保持。physics固定60，idle为实际外生delta；terminal沿原two-future-physics/首idle-preinternal，EOF/trailing仍原实现。生产fixed60-idle60/O(1)view完全不变。

SOURCE证明和模拟数据分开：新11文件接口仅解析严格载体、检查序/类型/身份并返回SOURCE证据；尚不创建bundle或读取expected。future adapter必须先验证fresh/ready/UI/RNG/四channel完整schema，再只投影runtime白名单。pre/act资源、准备后charges、crown、private/default、RNG checkpoint状态均只核来源，绝不能成为初始资源/过程分支/terminal指令。runtime仅含既有17键：checkpoint/environment/nodes/timer_lineage/initial_items/prepare_order/activate_order/frame_clock/king_particles/root_node/processing_nodes/inactive_auxiliaries/ui_authority及schema/mode/profile/terminal。

## 3. Realize

### Runtime函数

- genuine新常量：profile/case/observer版本、精确A canonical fixture SHA、A roles、six-items；PROFILES只新增此一项。`validate_single_king_fixture(fixture)` strict闭集class/ID/唯一King与精确A SHA；不能受外部layout或用户allowlist扩域。
- `validate_profile`/`validate_result_profile`/`observer_label`：仅新profile单独分派；输入与result各自仍核mode/terminal/fixture；不新增未知patch identity，validate_patch保持原AST，故新native patch尚未封时仍拒。
- `validate_single_king_ui_authority(rows)`：旧UI纯检查器复制为新封闭函数，仅改schema/case/39个确切A roles及case-specific错误文案；完整bind/ready/role/input-control/stack/window/unsupported0门保持，不仅相信bool readiness。
- 新RNG初始checkpoint检查器：旧pure helper改case/schema/sourceprofile命名，其余身份/位型/prepare-cut join保持；返回proof，永不构造或重设生成器。
- 新fresh validator：继承111 node/timer/particle/selected-facts类型检查，固定P:12、新schema，保全部fiveTimer birth/owner/no-start/default/private来源门；不得把generic Item ready当完整Timer样本。fresh facts和UI/root/King/particle/Timer实际身份必须交叉核；ready默认仍由真实scene/构造SOURCE与合法pre/act证明。
- engine `_integration_domain`新增精确profile；`validate_runtime_inputs` King分支增加精确profile并对新域核A/source默认initial limiter；`_validate_processing_inputs`仅新profile分派到新helper。新helper复用旧逐node/raw/model/flag/UI/particle关联算法，移除仅新域中的64/旧fixture特例，增加A相对SOURCE拓扑核验。真实native IDs、ancestor绝对index、clock offsets/deltas仍必须输入，不能代码猜测。
- King效果、prepare/finish/step/run/result、scaffold、driver/timer算法均不改；integration接线通过原分派自然生效，终态真实保flag/origin/crown/charges与FX。

### 新SOURCE工具及输入合同

`tests/phase355_input_source_contract.py` 只stdlib解析/校验，不定义build/main/模型入口。接口 `decode_sources(raw_by_name)`：精确11名字→bytes，每文件/行/总caps、UTF8/duplicate/非有限拒绝；四channel文件先严格归属/每文件递增/跨channel唯一sequence，再允许下游schema解析；primitive保原row顺序、K1拒global_u32，ABI原randf/randf_range/randi_range不改。新增clock/UI各用独立顺序，不伪称共享四channel sequence。

11类为fixture.json/player_fixture.json、四observer7 input/lineage/metadata/primitives、king-clock-checkpoint.json/king-clock-passes.jsonl/king-input-facts.json/king-ui-authority.jsonl/king-rng-checkpoint.json。固定file cap沿旧King：默认256MiB、clock passes64MiB、UI8MiB、rng16KiB、checkpoint/facts2MiB；总256MiB，record四channel2MiB/UI16KiB/clock1KiB，最多200000clock/65536UI，允许实际计数更小。原clock schema/lineage fixed60+真实idle不变；新facts/UI/RNG仅准确版本化。所有extra names（含events/runtime/alloc/final/history/endpoint）拒绝。

SOURCE工具 `validate_decoded_proofs(decoded, fixture)` 将来调用新genuine纯validator和原decode_clock，校验fixture、UI/RNG/fresh/input关联，只返回proof；本轮不调用。四channel全typed schema、新collector符号和真实输出carrier存在性须后续native SOURCE块闭合，工具明确 `BUNDLE_BUILD_NOT_IMPLEMENTED`，不以partial schema通过当input release。模型只能由将来的独立封adapter输出合法runtime+direct-return tape；strip白名单/负控在adapter实现阶段另验。

本轮封字段矩阵、11文件schema/caps、最小diff、15freeze、旧函数AST逆向证明及SOURCE依赖/pending列表。固定A的原layout与转换fixture、native seed提案在任何新运行前封。缺字段只能明确报缺输入，不默认填实际flags、native路径、Timer出生/prepare顺序或clock尾。
