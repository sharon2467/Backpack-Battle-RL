## 2. Design

Use a new owned directory and a three-file own project: minimal `project.godot`, `probe.gd` extending SceneTree, and fixed input JSON. No main_scene, autoload, resource load, Game script/assets, collector, native battle or shared pool. `_initialize` constructs exactly two built-in unscripted RandomNumberGenerator objects A/B. It reads their actual seed/state defaults before any setters; no randomize, wall-time seeding, yield or SceneTree processing is requested. B remains untouched throughout A's seed trajectories; later B state writes/draws must leave A unchanged.

The exact planned input is `data/phase456-native-rng-numeric-design/planned-inputs.json`. Five explicit semantic uint64 seeds, in order, are0,1,2^63−1,2^63,2^64−1. Their native setter arguments are the signed64 bit-pattern representatives, carried as canonical decimal strings rather than JSON numbers. A sixth trajectory is B's untouched constructor DEFAULT_SEED12047754176567800795: B receives no seed/state setter before its five numeric calls. This directly tests the default trajectory rather than inferring it from an explicit default setter.

For each explicit seed, A records the seed setter/readback and performs this one mixed sequence without intervening state override: randi; randi_range(INT−2,INT3); randi_range(INT7,INT7); randf; randf_range(INT−2,INT3). After all five A trajectories, B performs the same five calls directly from its constructor state while A stays unchanged. Singleton consumption is checked through actual post-state. The last call tests the finite small-INT-to-real_t binder route, not arbitrary Variant coercion. Reversed integer and reconstructed REAL/FMA witnesses already exist in140 and are not repeated. Then B receives state values0,2^63−1,2^63,2^64−1, each followed by one randi. This checks high-bit state writes, current_seed preservation on set_state and subsequent transition/return, while A stays fixed.

Planned totals: two constructors; five seed setters; four state setters; **34 numeric API invocations**, with **22 integer and12 REAL returns**: six times three integer/two REAL calls, plus four integer calls. No diagnostic tail draws. Getter observations and native internal PCG steps are counted separately. Native wire has exactly47 records: header1, constructor records2, five*(setter1+numeric5)=30, untouched-default numeric5, four*(setter1+numeric1)=8, footer1. Every mutation/draw records both objects before and after, including argument Variant types. Constructor A has only A available; constructor B adds B and rereads A.

Native integer scalar is exact `{type:'int',decimal:canonical_signed64}`; REAL is exact `{type:'float',binary64_be:16_lower_hex}` from StreamPeerBuffer.big_endian=true/put_double. No JSON float is authoritative. Setter records have actual arguments and property readbacks, with no invented native return; constructor records report actual getter defaults, not fabricated constructor return values. Closed per-kind schemas, fixed IDs/order, argument readback, exact47 records and a complete footer are mandatory. Native state/current_seed are actual signed64 INTs. After raw sealing, Python normalizes `u = signed & ((1<<64)-1)` and emits canonical uint64 decimal plus16hex; require signed range first and exact equality to that mapping. Never parse a64-bit value through float, abs or a JSON numeric cast. Native increment is not exposed; fixed sequence/increment is a Source premise, never a claimed native getter.

Reuse the existing138/394/401 runtime descriptors and363 generic monitor, not a new dependency investigation. The same offline wrapper SHA78beb697959d28b45c40f7a93174d22c67f711c077f5f7dcfb22ca10e69dd961 and pinned Xvfb/libsteam are indexed in394 and401. `evidence-map.json` distinguishes historical descriptors from current physical revalidation;456 does not rehash/execute the full runtime. Future Source preparation must verify needed actual leaves from that index, with no install/restore/rediscovery; missing/drifted runtime stops.

## 3. Realize

This phase writes only this four-section SPEC, the fixed proposed inputs, evidence map and design summary/owner. There is no runnable probe or runner in456.

Future preparation functions are intentionally small:

1. `verify_existing_evidence(root) -> receipts`: verify140 summary/owner/raw identity,142 summary/owner and exact current distributed two-module bytes against142.runtime_sources; verify138/401 binary SHA agreement. Reuse accepted140 route without regenerating predictions or running552 alternatives. Validate planned schema and exact finite input list. Fail on missing evidence or changed Source.
2. `freeze_project_and_predictions(root, inputs) -> owner`: write the three own-project files; pin original two modules plus relevant029 RNG/PCG definitions and binder source already indexed. Preseal expected complete47-record semantic stream using the accepted129/131/142 recurrence/rounding reference, independently checked before native launch. No Game/model or expected combat fields may be consulted. Expectations for defaults and every before/after untouched object are included. An independent reader must not derive expected values from native output. Candidate and reference outputs, if needed during preparation, are new component-only work with their own declared counts; not silently executed in456.
3. `probe._initialize()`: strict string-decimal input to native INT; verify readback type/value before any call; create A/B exactly once and record class/unscripted status; execute fixed operations in order with actual getters; append/flush each record, fail/quit2 on first script/protocol issue; footer/quit0 only on completion. No hidden RNG call in serializer, getters or diagnostics. Native internal engine startup randomness is not instrumented and is outside these two objects.
4. `launch_once(release, source_owner) -> process_receipt`: verify exact script/project/input/prediction/runner/runtime pins and accepted independent Source review; require a fresh exclusive attempt marker and native lock; launch once under363 monitor with declared budgets. Preserve raw result/logs/process receipt and immediately seal before interpreting. Recheck all input Source bytes; do not edit the current shared pool or depend on READY/Game restore helpers.
5. `normalize_and_compare(raw_bytes, pinned_expected) -> report`: stdlib strict JSONL/duplicate-key/type/canonical-width checks; require every fixed47 row and untouched-object snapshot; normalize signed64 only after raw seal; compare all returns/float bits/seed/state/arguments/ordering to one fixed expected stream. No tolerance, unordered comparison, truncated suffix, per-row alternative or missing default filled from Source. Store exact first difference and actual draw/getter counts.

Consumers remain unchanged. Current OriginalRNG inherits the exact GodotPCGInteger core; float32 CLZ/separate arithmetic is already140's accepted finite route. Current headless.CombatRandom creates OriginalRNG(combat_seed) and GodotPCGInteger(global_seed); initialize constructs a separate global provider for preparation shuffle and hands its post-preparation state to CombatRandom. The oracle tests native object primitives, not that Python domain-seed policy against Game. Domain seed hashing is an explicit synthetic Source policy; even numerically identical object initialization cannot prove the native Game chose those two seeds or made the same calls. No label/code promotion occurs in456 or automatically on a later PASS.
