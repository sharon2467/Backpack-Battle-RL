### Source rules and why this is a small extension

Original `Items/Exclusive/MagicMirror.gd` prepares total reflection chance `getChance()+getNumAffectedItems()*getChance2()`, accepts Holy targets, and performs `multiplyBuffsLimit` then `onAfterEffectFinished`. `Items/Item.gd::multiplyBuffsLimit` gives positive stacks through delayed logging; the following, separate `removeBuffsFraction` method calls `loseStacks`. They must not be conflated. `Items/FlyAgaric.gd` inflicts poison then activates. `Core/Buff.gd::gainTemporary` performs per-stack reflection, reflection-stack/resistance accounting and reflected recursion with its original source/event association; `reflect=True` prevents another reflection loop. Retain zero-percent rolls if Source calls them, strict raw `<=' semantics, amount/cap early returns and all selected RNG order. `Character.takeDamage`/the shared model nonitem damage path must still draw the fixed damage range before applying invulnerability. Invulnerability blocks damage while active; it does not erase a Poison stack gain or its history.

King's protected-buff count is a separate resource. The exact model production caller census found generic `remove_buffs_fraction`, `steal_buffs_fraction`, `remove_random_buffs` and `steal_random_buff` helpers without item production call sites in this selected engine. Garlic6 has a real `remove_stack(enemy,Vampirism,1,used=False)` caller, but no Vampirism producer exists in the proposed eight-ID domain. Adding6 alone does not hit protection; adding a second new family merely to furnish Vampirism is deferred. Mirror/Poison is therefore the shorter coherent family.

The existing Source factory derives Timer membership and native-free topology from the layout.21 and332 have no extra business Timer; keep33 timers, with ordinary receiver counts derived from actual items rather than fixed26/65/39/78 constants. The fresh Source object fields start from actual factory defaults and are modified by prepare; do not relabel them as native reused-object initial proofs. Mirror prepared reflection chance/cache and later `consumed`/cooldown state are actual mutable state, not editable proof flags. Headless already registers Mirror `fraction_shuffle:<id>:<side>:multiply` global contexts and carries the global stream state after preparation; preserve that route and the complete combat-provider audit. There is no custom-native same-seed claim or numeric probe requirement.
