### Exact three-stage battle behavior

**Preparation/start.** Generic Item.prepare resets its balanced chance/damage range and caches; all preCombatStart cooldown setup precedes combatStart. The Whelp's `onCombatStart` calls `inflictRandomDebuffs(getP1())` then `activate(null,false)`. Four picks draw from all three categories `[Poison108,Blind109,Cold110]`, irrespective of prior target stacks. All selections happen before applying the picked dictionary under delayed logging. Repeated selected types aggregate; application follows first-selected-key insertion order, not sorted categories or pick-by-pick emission. Reflection/resistance/cap and history order remain the shared gain pipeline. Calls use default null parent. The actual startup Activation occurs after the entire burst; `playCombatAni=false` is a presentation argument, not permission to omit the Activation, metric/listeners or tooltip.

**Attack admission and early effect.** Inherited Weapon.doCooldownEffect uses the existing stamina gate (cost0), attack→dealDamage→activate path. Character.takeDamage determines effect-count/accuracy before the own early hook. `AmethystWhelp.onPreDealDamage_early` checks **hit**, not positive damage, and calls `removeRandomBuffs(1)` with its default null parent. Thus a hit later reduced to0 by block/invulnerability still removes a buff; a miss does not pick/remove. The early removal occurs before damage-range/crit draws and before the Attack event exists. Do not invent an Attack parent or use `damageRes.event`. Existing `pre_item_damage(item,hit)` is the correct seam. The default-zero double-attack-effect roll can succeed at raw0; repeat only the own early removal for each effect count, not the entire attack/common signal/activation. Keep the actual helper's empty-selection delayed logging behavior and full caller continuation.

**Damage types.**201 has both Ranged and Effect types. `DamageSource.setItem` yields types `[Ranged,Effect]` but chooses Ranged flags63; `isAttack()` remains true. It must use the ordinary ranged attack pipeline, not the pure Effect `take_effect_damage`/Blood-Goobert path. Effect does not suppress the accuracy roll, own early hook, attack damage reduction or ordinary activation. Current fresh default characters have ranged/effect Spikes limits0, ranged Vampirism limit0 and typed-damage factors0, and the supported Source default family has no writer enabling nonzero typed damage factors. Those bounds justify reusing the current ranged branch, not deleting flags or asserting that a dual-type weapon can never proc nonzero effects. Arbitrary mutable typed-damage factors/limit overrides remain outside the public layout domain. Positive base damage means201 is empowerable; add it to the existing finite empowerable-weapon set so Whetstone, Steel/Crossblade secondary eligibility and corresponding boosts see the real Weapon. Existing RangerBag67 current crit/accuracy, buff producers, Mirror reflection and shields can be tested without a new subsystem.

The original Whelp script has only the two battle overrides and no direct Squirrel-style Util pitch override. Do not add164's extra activation draw to201. Existing shared presentation/native-session exclusions remain scoped as before; this is not a full session RNG proof. Future native comparison must use actual selected primitive Tape and explicit new Source bindings, not produced seed equality.
