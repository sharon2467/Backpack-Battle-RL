### Actual repetition pipeline, RNG, timing and parents

`Item.hasAttackEffect`4126–4129 is the OR of the onready method-existence flags500–502 for own `onPreDealDamage_early`, `onPreDealDamage_late`, `onDealtDamage`. Preserve the Shortbow's separate `Item.rollChance`4390–4394/`chanceRng` state and calls on each repeated own callback; do not merge it with the effect-count flip or reuse its return.

Original `Character.takeDamage`494–655 computes one attackEffectCount before accuracy, after its dead guard. It emits common early once, then repeats own early overrides even on a miss; hit-only damage/random damage/crit/resistance/invulnerability/shield/block/health pipeline remains one pipeline; common late is once and own late repeats only on hit, including zero damage. It allocates one attack/miss event and emits common attacked/damaged once, then repeats own dealt overrides only for an Attack source. Existing passive spikes/vampirism/death ordering stays. Do not recalculate count after an early effect changes state or add an ended short circuit inside these loops.

The accepted545 `attack` already carries these three own-hook loops. It must remain byte-exact if the finite receiver controls confirm the stated correspondence. The Skill's cooldown least-buff grants keep their default/null parent and current logging mode; no new Skill event is made a parent of weapon effects. Existing `weapon_attack` still activates once and pays stamina/cooldown once. A repeated own effect is not two attack events or two Activations.

No TimerRuntime, FrameDriver, clock policy, RNG algorithm, allocator, attack/history/queue kernel or native schema change is needed.385 is a cooldown Item and participates in existing preparation/start/scheduling orders.
