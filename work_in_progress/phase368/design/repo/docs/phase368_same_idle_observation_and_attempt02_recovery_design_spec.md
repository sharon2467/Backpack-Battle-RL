## 2. Design

### Choose a synchronous, private observation signal inside the existing sink callback

Future368 sink declares an observation-only `source_idle_cut_ready` signal with no parameters. Collector connects only to this sink signal: exactly one receiver, target=self, exact method `on_idle_source_cut`, flags INT0, empty binds. The collector no longer connects its cut callback to SceneTree.idle_frame. Existing SceneTree connections (including collector.observe and sink.clock_idle_signal) stay intact: no reconnecting, reprioritizing or removing original listeners. Tables preserve their actual engine order/ObjectIDs; no timing-of-connect assumption replaces them.

At the eligible tail of `clock_idle_signal`, retain the original clock/UI/endpoint operations and their order. Only after all writes flush successfully and `source_window_complete=true`, `closed=true`, `king_clock_closed=true`, `ui_closed=true`, `failed=false`, the sink synchronously emits the private signal while still inside its own SceneTree.idle_frame handler. Flags0 dispatch uses `target->call`, not MessageQueue. The collector freezes its existing full DTO exactly once on this nested call. SceneTree::idle cannot reach its MessageQueue flush or `_notify_group_pause(idle_process_internal)` until the outer idle_frame emission returns. This call-stack ordering establishes the cut independently of collector/sink ObjectID ordering.

The private signal may have only the collector receiver; otherwise fail closed before fixture birth and again before emission. Capture complete connection rows, target ObjectID/type, method, flags, binds-count, exact receiver count and duplicates. Nonempty binds, extra receiver, deferred/oneshot/reference-counted flags, changed identities or a second emission are rejected. The signal name is never passed through EventBus.emitAndLog or the generic observed-event recorder. Do not add it to the runtime site matrix or schema record stream. Its evidence is a separate control DTO; neither observer.sequence nor UI/clock sequence is incremented by control diagnostics.

`source_cut_emitting` and an observation-only emit count/frame stamp bracket synchronous emission. Collector requires that bracket, exact live observer ID and same physics/idle stamp; checks existing source receipt, result and barrier; then uses the unchanged approved fullsnapshot/getStats/read-only sampling. No callback loops back into clock_idle_signal or re-emits the signal. All emit/callback outcomes are stored as primitive controls. A diagnostic writer failure is secondary and must not overwrite collector-first-failure or observer.first_error.

### Emit/no-emit truth table

No signal on failed or already-closed entry, inactive/nonterminal idle, absent cleanup, earlier-than-two physics, missed-first-idle, clock_pass failure, endpoint write failure, final-source snapshot/write failure, UI-close failure, invalid connection table, duplicate emission or recursion. Do not silently report these as successful completion. On ordinary nonterminal idle, keep original clock behavior and return without emitting. At terminal idle: check clock_pass success via actual failed/clock state, require exact cleanup+2; call existing close_king_clock, final-source write, ui_close in original order; set completion flags; validate private connection and emission bracket; emit once synchronously. After emit, store its actual Error result and callback acknowledgement before returning. Any signal/ack failure leaves capture incomplete and preserves the first control failure; it cannot synthesize a missing DTO or reopen closed clock/UI writers.

The present helper `ui_check_controls()` return is ignored at clock entry; future implementation must explicitly stop after its false/failed result rather than continue to emit. This is control-only fail-closed behavior, not a business algorithm change. Source of each new guard is listed in the interface contract; diagnostics are written before rejection, not reconstructed after the run.

### Alternatives and influence on original listeners

A direct registered collector hook at the same sink tail could give the same call-stack boundary, but adds object lifecycle/invocation registration and offers less built-in receiver/flags evidence. A separately created relay could sort after sink by ObjectID, but intervening callbacks and lifecycle/reallocation still require proofs; it adds a node and does not by itself establish adjacency. Prefer one private synchronous signal and exact sole-receiver check.

No original SceneTree listener is moved or disconnected. Remaining idle_frame receivers execute in their existing order after sink returns. Sampling consumes wall time, as all instrumentation does; observed next idle deltas remain genuinely exogenous. `SceneTree.quit` sets `_quit` rather than synchronously skipping the remaining signal listeners. Preserve the current quit request behavior after frozen DTO serialization; do not claim instrumentation has zero timing cost or alter business subscriptions to compensate.

### Bounded primitive diagnostic before every source admission rejection

The scope is source-window/listener/precondition/cut guards and their immediate control callers, not a new global event auditor. Replace compound short-circuit rejection with named reason branches. For each rejected path, first collect/retain a complete primitive snapshot: reason/site/stage, current physics+idle/in_physics, original observer sequence, UI/clock counters, observer/collector/tree IDs, observer present/failed/first_error primitive fields, ui_opened/ui_closed/closed/configured/metadata_ready/source_fixture_window/source_window_complete, source_listener_attached, signal existence, is_connected results, attempted connect and actual Error return, full SceneTree/private-signal connection tables, match indices/counts/duplicates, emit bracket and result. Absent values are null with explicit availability; do not invent IDs, success returns or an actual first predicate for old attempt02.

Capture the whole table before checking duplicates/indices/flags, so early false paths retain `seen`. Project rows to known primitives only: no arbitrary Object stringification, `getDataPersistent`, affected-item getters or event-object retention. Native IDs use the existing decimal-string convention; raw row ordinal/type/method/flags/binds count are preserved. Failed begin_fixture_window/bind_fixed_inventory results include the sink's actual saved first_error and call/result marker. `place_player_items` records whether the first descriptor/instantiate/geometry branch was reached, with actual slot/descriptor primitives on a later rejection; this diagnoses control flow without changing the placement algorithm.

Proposed control file `source-window-diagnostic.jsonl`: max64 records, max256KiB/record, max1MiB total, max1024 connection rows/table. Record schema has `complete_seen` and explicit original row count. Over-cap or unsupported fields fail capture with CAP/UNSUPPORTED control; never truncate and claim complete evidence. Diagnostic failure status is retained in memory and bounded stderr fallback, secondary to the already chosen primary. No recursive call to fail→diagnostic→fail. Host archives this control opaquely, and its bytes count toward the existing monitored attempt budget. It is not a new lawful model-input carrier and does not modify the accepted12 projection ABI.
