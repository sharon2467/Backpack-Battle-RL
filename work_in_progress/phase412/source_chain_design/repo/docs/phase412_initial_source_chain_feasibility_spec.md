# Phase412 initial SOURCE-chain feasibility design

## 1. Requirements

This is a SOURCE/design review of the 88 unresolved initial targets retained by the first actual Phase411 stdlib audit. It does not execute an audit, schema, reader, candidate, model, FrameDriver or native process, and does not read any original run/capture input, EXPECTED stream, endpoint, cleanup or final state. Phase411's saved initial index is the only actual-value carrier consulted. A pointer in that index is a citation, not permission to open its target. Old403/405/408/411 artifacts remain immutable.

The independent Phase411 result is 1,479 required targets: 1,391 DIRECT_OBSERVATION/SUPPORTED, 88 MISSING/UNPROVEN, zero rejected domains. The 88 are exactly 12 Character fields, six King fields and 70 Timer private values (35 distinct roles at two initial phases). That result establishes neither full-schema validity nor a genuine input bundle. No subsequent SOURCE-only argument silently changes the old audit result.

For each target, distinguish: (a) whether an actual initial direct carrier was retained, (b) which SOURCE edges are established, (c) which specific edge is unproved, and (d) whether another SOURCE file or an already-existing lawful initial observation could close it. MISSING means an unresolved proof obligation, not a finding that the original capture lacks the information or that recapture is necessary. No default, public Timer zero, later snapshot, model trajectory or convenient Boolean is a substitute for the proof.

A completed SOURCE_DERIVED recipe must identify the actual object/owner, allocation/configuration, all relevant writers and their interval, the initial phase, and the resulting exact native type/domain. It must survive independently rereading the cited source and initial index. A conditional recipe with an unproved edge remains MISSING. Native private Timer values cannot be DIRECT_OBSERVATION in the current index.

### 2.2 Native Timer rules established from the four saved C++ files

`Timer::Timer` sets private double `time_left=-1`, `processing=false`, `paused=false`, idle mode, wait_time float1, autostart=false and one_shot=false. `start(float)` rejects a node outside the tree, optionally assigns positive wait_time, then sets private time_left=wait_time and enables processing. `stop()` sets exactly-1, disables processing and clears autostart. `set_wait_time` only changes wait_time; changing one_shot/autostart does not itself change private time_left. `set_paused` changes processing registration without changing time_left. `set_timer_process_mode` moves internal registrations. These distinctions are part of the proof, not a simulation.

`get_time_left()` clamps every private value<=0 to public float0. `is_stopped()` is `get_time_left()<=0`, not `processing==false`. Therefore public0/stopped=true cannot determine private-1. Even all current flags=false are not a universal inversion: Node exposes `set_process_internal`/`set_physics_process_internal`, which can remove registration independently of Timer's private processing/time_left. A conceptual counterexample is an exact-zero countdown followed by a direct internal-registration disable; this is not asserted to have occurred and is not executed here. A proof must exclude that writer route for the actual role.

Both native Timer notifications require processing, the appropriate mode and the matching internal flag. They subtract the actual frame delta and trigger only when private time_left<0. One-shot stop occurs before timeout signal delivery; repeating timers add wait_time before the signal and can carry a noncanonical negative value if a large delta exceeds the repeat interval. Thus a previous repeat tick cannot be replaced by a constructor default without history/writer evidence. Child readiness precedes parent readiness (`Node::_propagate_ready`); Timer autostart may run in child READY before a Character parent records birth. Autostart clears itself after starting, so current/birth autostart=false alone does not exclude that earlier start.

SceneTree physics_frame precedes internal physics dispatch, while idle_frame precedes message-queue flush and internal idle dispatch. Delayed SceneTreeTimer callbacks occur later in idle, distinct from native Timer nodes. This explains why the 2.5s prepare-to-activate interval is not an atomic no-writer interval. These rules do not change the accepted391 first-actual-eligible-idle contract and are not a new terminal/replay validation.

The four saved files are byte-identical to the Phase251 freeze. Phase251 records their saved origin under phase027/full-source/upstream and labels them Godot3.6.2, with a static-only receipt. The currently authorized provenance does not itself supply a build commit/compiler proof of the actual executable. No network fetch or runtime query is performed. A later accepted recipe must retain the existing version/source-binding authority or obtain a narrowly scoped saved provenance receipt; no new model/native run is needed to establish file attribution.

### 2.3 Five birth-ledger Timers: established edges and remaining obligations

For both AutoHide roles, `_ready` executes `timer=Timer.new()`, immediately records birth, then sets one_shot=true, connects timeout, adds the child and hides the particle. The two recorded births are outside-tree Timer objects, idle mode, one_shot=false, wait1, no internal processing. This is a much stronger constructor edge than the other roles. The code has one start call in `startTimer`, reached from one-shot activate or visible deactivate. Activate and instantClear stop the Timer. Every explicit call in this owner script uses timer_before/after. Native READY autostart must be separately excluded; constructor/default and the interval's property writers matter. Current particle visible/emitting/one_shot=false corroborates the end of the interval but is not evidence that deactivate was never called.

For king_buff, `scene_instance` records birth outside the tree after scene instantiation. The King scene explicitly gives BuffTimer process_mode0/one_shot=true and a timeout→buffEnded connection; it does not set autostart. The only explicit King start is doCooldownEffect after consuming a charge; onCombatEnd stops. The newly authorized full inherited Item scene body has now been checked: its embedded tracks do not target BuffTimer/these AutoHide Timers. External animation/script callbacks remain distinct dependencies, so all actual direct/reflected Timer mutation paths are not yet closed before converting starts0 into an exhaustive no-start theorem.

For invu:P/O, Character records birth as the first statement of its parent `_ready`, after child READY. The base scene explicitly sets the Timer mode0/one_shot=true and connects timeout→invulnerabilityEnded. The inherited Player/Opponent scenes preserve these node configurations and the Character root script. They do not by themselves prove the absence of every child callback or external animation method track before/after the recorded birth. Parent-ready birth is not constructor birth.

`timer_before` increments the five-Timer ledger before checking failed/closed/source_fixture_bound. `timer_birth` refuses reuse and stores counters0. The retained five records all have starts0/stops0. Thus source_fixture_bound being late does not erase earlier *instrumented* starts, and a complete no-start proof can span reuse, pre_prepare and pre_activate. Counters cover only the hooks: they do not intercept C++ autostart, arbitrary direct Timer.start or Node process setters. The immutable record label `source_constructor_minus_one_no_start_not_public_zero_inference` is a claim to be proved, not an accepted proof flag.

The precise conditional recipe is: verify actual IDs/owner and phase join → prove constructor-to-birth interval (different for each role) → prove complete start/autostart/internal-state writer coverage through the facts observation → use count0 and the native no-processing guard to preserve private-1 → corroborate both checkpoint public/configuration values. Stops, if present and fully ordered, could independently reset-1, but these actual five stop counts are0. This recipe is admissible only after every edge closes; its desired value is not an assigned initial input here.

## 3. Realize: reviewable proof procedure, not executable implementation

No new callable API is introduced. `source-anchors.json` supplies exact existing function/range APIs and byte hashes. The proof ledger is declarative evidence, not executable code or a truthy proof graph.

1. Read only the pinned411 output index and SOURCE scope. Verify each file's type, nlink1, path and exact size/SHA before use. Keep any added Root-scope supplement explicit. Never join an absolute source path under a write destination.
2. Select the exact88 existing MISSING keys `(field_id,phase,side_or_role)`. Preserve their initial-index positions and produce one unique ledger row for each. Retain direct corroboration separately; do not promote its input pointer into a direct carrier for an absent field.
3. For each of35 Timer roles, record its native ID at both phases, precise public/configuration rows, owner relation where actually retained, allocation source, native start/stop/configuration/notification semantics, and role-specific writer methods. Use five counters only for their exact five IDs.
4. For Character, separately prove declaration/scene configuration, initial allocation/reuse and writer interval. For King, separate pre_prepare from pre_activate and distinguish actual charges from crown event history and light properties. An established method body is not proof it ran to completion.
5. Record each edge as established SOURCE fact, established initial observation, or unresolved obligation, with the named missing evidence. SOURCE_DERIVED is available only for a complete chain, not for a prefix. Keep the desired conditional domain out of `actual_value` while incomplete.
6. Prefer the smallest missing SOURCE/receipt or a narrow projection of *already lawful initial* lineage/configuration data over new native capture. An initial snapshot may be proposed only after this cheaper route is assessed. Proposals are not permissions and are not generated as runnable tools in412.
7. Seal finite pins, anchors, ledger, next-evidence plan, author observations and summary with an owned-files manifest. Independent review must confirm the chain claims before any future implementation or structural API release. Original356/361 remain CLOSED, fullschema NOT_VALIDATED, King not admitted and model/inputbuild0.

## 4. Acceptance Criteria / Tests

These are document/static consistency checks only. No original API is imported or called.

A01: finite read scope plus supplements contains every consumed source/output; every file remains ordinary single-link and exactly pinned. No original run/capture, EXPECTED, runtime state, pool, proc or network access occurs.

A02: 88 unique target keys equal the saved initial index's MISSING set exactly:12Character+6King+70Timer. Both phases and all35roles are represented. No target silently disappears because a proof is inconvenient.

A03: every direct support reference points to the exact retained index row; pre_prepare/activate shared sequences138/1231 and native owner/Timer IDs are preserved. Facts have pointer/source association, not an invented sequence. No missing target receives an actual_value from a default or endpoint.

A04: C++ constructor/private double, public clamp, strict<0 timeout, stop-before-signal, autostart READY, child-before-parent READY and independent Node process setters are separately documented. Phase251 static attribution is not overstated as actual native execution acceptance.

A05: five-role birth/owner/current/starts/stops are separate from exhaustive writer coverage. Parent-ready birth is not relabeled constructor birth; zero hook counts are not global native call counts. The30other roles have independent evidence and unresolved edges.

A06: PLAYER reuse is preserved; Character field-specific writers and reset differences are considered. King charges0→3 is not crown0; light modulate/self_modulate and pre/act intervals are not conflated. Every SOURCE_DERIVED claim, if any, has all edges and native types proved; incomplete routes remain explicitly UNPROVEN.

A07: next evidence is finite and ordered SOURCE first → existing lawful initial evidence projection if necessary → new native input observation only as a last separately authorized option. No request to use EXPECTED history as INPUT, no automatic recapture, no candidate/reader implementation.

A08: owner closure and static summary agree. Source-chain design does not upgrade old411, fullschema/genuine-input or King/model gates. All author operational audit/SUT/schema/model/native calls are0; ordinary author JSON/text/hash commands are disclosed separately. Independent acceptance is pending.
