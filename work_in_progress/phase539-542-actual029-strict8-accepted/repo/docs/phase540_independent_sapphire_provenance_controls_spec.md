# Phase540: independent Sapphire provenance controls

## 1. Requirements

Validate only the immutable phase539 repair after its actual API and Source freeze arrive. Preserve phase533/535 output, phase536 first failure and the unchanged eight-section comparison semantics. This plan authorizes no execution by itself. At most five directed cases; no candidate import, model rerun, Native, Expected read, B2 extraction, or old suite replay. Phase538 design acceptance is not implementation or comparison acceptance.

## 2. Design

One future isolated process authenticates exact539 adapter/source owner, the original sealed535 model and prepare gate, accepted input/proof, and the frozen537 addendum. Actual auxiliary arguments and closed binding keys follow the frozen539 API. The model and gate must be members of the same original output seal and request chain. Read the real model/gate only in the later released batch; do not create fake complete captures or engines.

The positive case projects the model final state using the original measured gate. Independently assert that final P:14 stackTypes is an ordered list of exactly six strict INT values equal to the authenticated gate view, with no catalog/witness/Expected fallback. This checks model-side mapping only, not Native equality.

Four negative cases each alter one frozen in-memory input boundary. Record the actual first rejected predicate, not the deepest intended condition. A modified gate may fail canonical identity before report/type validation; this is expected and must not be described as deep typed branch execution. Do not rebind a mutated gate canonical hash merely to reach deeper checks.

## 3. Realize

No harness is implemented or executed at this planning step. After539 freeze, independently review the mechanical Source delta, explicit auxiliary parameter propagation, fixed gate/addendum binding, final identity validation and unchanged other comparison projections. Bind the exact callable names, dependencies, vector bytes and invocation count in a new sealed harness artifact without modifying this plan.

Cases:

1. Original authenticated sealed model plus gate: call the actual repaired model-final projection; require the measured ordered six-INT field and original final identity.
2. Missing gate descriptor/binding field: reject the closed binding before any fallback. Choose the exact missing field after539 API freeze; one case only.
3. Gate content mutation with original binding/canonical hash retained: reject canonical gate identity.
4. Gate report/view disagreement (mutate one report element only; view and original binding unchanged): reject at the actual first guard, which may again be canonical authentication. No claim of deeper list/type coverage.
5. Final P:14 item_index changed from strict199 to a different INT, original gate and binding retained: reject final item identity; no mutation of original files.

The actual public/model-final call and any necessary binding construction helper calls are separately counted; nested guards are not additional test cases. The five-case limit is not a reason to introduce wrappers that hide calls. Exact call counts and a modest fixed wall limit will be sealed after the real API is known. First unexpected failure stops the batch and preserves output; no auto-fix/retry.

## 4. Acceptance Criteria / Tests

Source delta accepted, original evidence authenticated, one positive and four expected rejections with actual first rejection sites recorded, source identities unchanged after execution, no unapproved imports or reads. Preserve original outputs and phase536 failure. A pass permits Root to release a new strict-eight comparison host using the same535 model and same nine Expected descriptors, changing only adapter/version bindings plus explicit original gate/addendum. It does not itself establish business equality or formal/general support. The comparison is a separate invocation and cannot be folded into these controls without release.
