# 365 control failure and exact recovery SOURCE implementation

## 1. Requirements

Implement the accepted narrow design without changing its frozen 9440-byte SPEC or any old SOURCE/evidence. The independent364 language probe is evidence of the BOOL caller defect, not acceptance of the new code. This turn generates SOURCE, compiles text, verifies AST/byte identities, and seals an owner. No helper, pool, Godot, process monitor, projection or model execution. Native attempt01 remains failed; a future attempt02 uses identical case/fixtures/seeds.

## 2. Design

The new collector adds one config-only comparator: exact top-level keys, strict BOOL true for player_fixture_enabled, applied to the raw parsed config (so missing keys cannot inherit defaults), then duplicate/remove that key and delegate the remaining tree to the unchanged359 slot comparator. P/O validation, SOURCE constants, getter/effect/clock code remain byte identical.

The new host retains363 storage/process. After the real process returns it freezes process and partial capture metadata before interpreting validation. Only bounded collector control JSON and validation JSON are decoded; all other expected files are opaque hashes. Present lawful files and missing names are separate. Missing/bad validation is secondary to the collector control failure, incomplete captures cannot reach archive/READY, and rename failures also preserve the process result. The future root/source review gate and attempt02 protocol are distinct from363; no future accepted pin is invented.

Recovery is separate from oracle execution. Explicit source_root/pool/baseline/failed_run/previous_run roots replace historical map prefixes. A root-config descriptor binds the new SOURCE owner/freeze, the frozen design map/input pins, and real independent SOURCE review. Restore requires an exclusive pool lock, no live pool/run references, exact failed state bytes, complete current tree equal to preserved manifests, all previous bundle/overlay/driver hashes and all restore payloads before mutation. It restores only mapped78 project files and2 staged files atomically, applies full target directory metadata deepest first, then reads both complete trees twice. The restore receipt retains failed state and explicitly is not independent readback. Failure keeps partial journal and state failed; no rollback/deletion/retry.

READY is a separate root action. Its config must bind an actual owned independent readback report with exact roots, map descriptor, restore receipt descriptor, project/data target descriptors, failed state identity, and PASS status. The helper verifies current full trees again before the sole transactional state update. A BOOL or author report cannot substitute for that independent report. No native launch is part of either action.

## 3. Realize

- `config_matches_source(value)` adds the strict local BOOL/key gate and delegates all other fields; only its `_initialize` call site changes.
- `collect_capture_metadata(run,result)` catches rename/control/validation failures, emits present/missing lawful identities, opaque expected identities, bounded primary/secondary controls, and source/project status. `execute` writes process_result/source-partition before its single failure return.
- `source_gate` on the new host uses the new actual SOURCE/review schema; `plan`/`execute` preserve old mechanisms with attempt02 and collector path only.
- `verify_evidence(roots,map)` validates the frozen input-pin list, preservation receipt/overlay CRC/SHA, old bundle, exact map deltas and all regular+nlink1 payloads. It has no mutation.
- `locked_pool` rejects active references and holds `.lock`; `restore_exact` rechecks complete preimages, writes an intent journal before mutation, atomically writes payloads preserving target metadata, restores directory metadata, emits an engineering receipt while state remains failed. Exceptions emit failure journal plus best-effort actual inventories/capture_error, never fabricate missing state.
- `commit_ready` requires a separate real root action and owned independent readback; it revalidates the restore receipt, target/root/source identity and actual tree before state replacement. The old bundle inventory is used verbatim; postcommit old `check_ready` is verification only.
- A text-only preparation script derives collector/host, creates exact diffs/inverse assertions, carries363 storage/process byte identities, checks old owners and canonical/runtime15, and seals a combined SOURCE freeze plus owner. It never imports generated helpers.

Root config schemas: `phase365-root-oracle-acceptance/1` and `phase365-root-pool-recovery/1`; proposed independent SOURCE status is `INDEPENDENT365_CONTROL_RECOVERY_SOURCE_ACCEPTED_ROOT_PENDING`, used only when an actual receipt exists. Recovery requires `action` equal `restore` or `commit_ready` and the corresponding strict root authorization true. Independent readback status is `INDEPENDENT365_RESTORED_POOL_EXACT_TARGET_READBACK_PASS`; report and owner descriptors are exact repository-relative files, validated before commit.

## 4. Acceptance Criteria / Tests

This turn: compile only, collector inverse byte equality, host unchanged-function AST comparison, old SOURCE/failed evidence identities and all new owner leaves read back. No SOURCE semantic acceptance is self-signed.

Future independent controls: config true positive and false/INT/REAL/missing/extra/seed/timeout negatives; no-validation/bad-validation/partial12/rename failure retain first collector failure and process exit with opaque expected reads only. TinyFS recovery must reject hardlinks, bad before/payload/map/bundle, extra paths, mismatched roots, missing/forged independent report and premature READY; successful restore leaves failed, complete independent readback permits only separate exact commit. Actual failedpool restoration and native attempt02 require new root gates after those SOURCE controls.
