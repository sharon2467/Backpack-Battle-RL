## 2. Design

`Item.gd5513–5545` requires virtual selection before all grants. Build an insertion-ordered local count dictionary for the requested beneficial categories101..107. For each requested unit, scan it with the Original integer sentinel10000, make one `randi_range` choice even for a singleton, increment the virtual count and accumulate in first-selected category order. Only after all selections call existing `give_stack` for each aggregate, using the original parent and **current** logging mode. No delayed logging switch or queue flush. If a positive request has no candidates under the sentinel, reject that unsupported domain explicitly rather than replacing10000 with infinity. Zero/negative requests perform no selection, as the Original `while numStacks > 0` does. Public category validation remains finite and beneficial-only; no arbitrary allocator framework.

Prepare for231 calls `add_speed(count * p3 / 100.0)` even when count is zero, then registers the listener, then computes `(p1 * character.base_stamina_regen) / 100.0`. A dataclass BOOL registration field and optional REAL prepared coefficient represent this actual lifetime; construction does not register a listener. Existing preparation order is the receiver order. No prepare Activation.

That call uses the **current global event_num**. It must not use queued event.id, next_event or allocate an event. Already-dispatched amount0 still calls the helper and snapshot; normal cap/resisted/protectedzero operations retain existing no-emission behavior. Existing history dedup may suppress a row despite the snapshot call. Existing queue and ended handling remain authoritative. Existing character ticks read the changed live regeneration with unchanged Timer/FrameDriver code.

The existing explicit `initialize_experimental_nonking` interface extends its closed extra set from `{64,164,197,199,201}` to `{64,164,197,199,201,231}`. Class0/default/noKing/noGems/rage restrictions and at-least-one-experimental-item remain. No per-item API, user allowlist, new listener bus or new provider gate. Source RNG labels are explicit (`least_buff:<identity>:<target>:<ordinal>`); they are not claims about a Native caller context or seed parity.
